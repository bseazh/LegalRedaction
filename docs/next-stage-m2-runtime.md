# 下一阶段：M2 本地运行时验证

## 阶段目标

验证已下载的 HaS Text 0.6B FP16 是否适合在当前设备运行：

- 设备：Apple M2、16GB、macOS 14.8.1
- 模型：`models/has/HaS_Text_0209_0.6B/`
- 输出：一份可复现的 M2 性能与可靠性报告

这一阶段只做实验，不接入桌面软件，不处理真实案件原文，不决定最终安装包方案。

## 执行顺序

### 1. 选择本地运行时

优先尝试 MLX/MLX-LM，因为它适合 Apple Silicon，并可以直接读取 Transformers safetensors。`llama.cpp` 需要 GGUF 格式，不能直接把当前 safetensors 文件当作 GGUF 使用。

如果 MLX-LM 在当前 Python/macOS 环境无法稳定安装，再建立隔离环境测试 Transformers + PyTorch MPS。运行时只放在实验环境，不写入应用目录。

### 2. 启动最小推理

使用 HaS 官方 NER prompt，不自行改写第一轮模板：

```text
Recognize the following entity types in the text.
Specified types:["姓名","机构","电话","案号"]
<text>...</text>
```

先用合成文本，再用已经人工确认可使用的脱敏样本。不要直接把未脱敏材料写入日志。

### 3. 测量性能

至少运行 5 次相同请求，记录：

- 首次模型加载时间；
- 首次请求延迟；
- 后续请求平均/最大延迟；
- 输入 token 数、输出 token 数；
- prefill/decode tok/s（运行时能提供时）；
- Python 进程和模型进程峰值内存；
- MPS/Metal 是否启用；
- 连续运行 10 分钟是否崩溃或明显变慢。

### 4. 测量输出可靠性

每次响应都必须经过以下检查：

1. 是否能提取出预期实体结构；
2. 实体类型是否属于请求类型；
3. 实体 value 是否确实出现在原文；
4. 同一个 value 多次出现时是否能定位到正确位置；
5. offset 是否符合 Python 半开区间 `[start, end)`；
6. 模型是否产生幻觉实体、重复实体或跨边界实体；
7. 同一实体在多轮/多段文本中是否保持一致标识。

解析失败、offset 错误或实体值无法回到原文时，结果必须进入人工确认，不能自动脱敏。

### 5. 与规则基线比较

使用现有 `test-data/ner-gold.jsonl` 和新增的人工标注样本，比较：

- 规则方案；
- FP16 NER；
- 规则 + FP16 NER。

指标：exact-span precision、recall、F1、每类实体结果、平均延迟、人工修正次数。

## 阶段验收标准

只有同时满足以下条件，FP16 才能进入下一步桌面集成评估：

- M2 上连续 10 次推理无崩溃；
- 模型进程峰值内存不导致系统明显换页；
- 姓名、机构、地址等语义实体相对规则基线有可测提升；
- 输出实体值和 offset 的自动校验通过率达到预设阈值；
- 规则 + NER 的误报率没有明显恶化；
- 结果可以被人工复核，而不是黑盒自动打码。

如果 FP16 的速度或内存不合格，下一步只比较 HaS Q8，不引入更大模型；如果 FP16 已满足要求，则不需要为了追求更高分数增加模型规模。

## 当前不做

- 不打包进 Tauri 安装包；
- 不接 OCR 和扫描 PDF；
- 不用真实案件原文做自动化回归；
- 不把模型输出直接送入 Tokenization；
- 不用官方 M4 Pro benchmark 代替当前 M2 实测。
